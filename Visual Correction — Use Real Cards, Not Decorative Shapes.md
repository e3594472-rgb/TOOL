# Visual Correction — Use Real Cards, Not Decorative Shapes

The previous redesign is still too close to a standard list UI with decorative elements.

This is **not** the visual direction I want.

## Important correction

When I say **cards**, I mean **real visible cards as the main UI object**, not just a plain list with card-like decorations in the background.

The result area should not look like:

- a normal vertical list;
- long white rows;
- list items with small badges;
- a simple dashboard with decorative shapes.

Instead, it should look like:

- a set of **large flashcards / game cards**;
- visually distinct individual cards;
- cards that feel like part of a classroom game.

## Main rule

**Each result item must itself be a card.**

Not a row.  
Not a list line.  
Not a standard card container with a list inside.  
The actual result items should visually read as separate cards.

---

# 1. Set the Order — exact visual direction

For **Set the Order**, do not display the result as a simple ordered list.

Instead, show the speaking order as **a deck of large numbered speaking cards**.

## Desired appearance

Each student should be shown on an individual card with:

- rounded rectangle shape;
- clear card border or layered surface;
- soft shadow;
- slightly playful but clean design;
- a number badge integrated into the card;
- student name as the main text;
- enough spacing so each card feels separate.

The cards should visually feel like:

- flashcards;
- game cards;
- speaking prompt cards;
- classroom order cards.

## Layout

Use a **card grid or stacked layout**, not plain rows.

Possible layout ideas:

### Option A — staggered grid
Show the cards in a 2-column layout, where every result is a separate large card.

### Option B — slightly stacked / dealt cards
Show cards as if they were placed on the table one by one.

### Option C — vertical stack with clear card bodies
If vertical layout is used, each item must still look like a full card, not a row.

## Very important

Do **not** use long horizontal white bars with a number on the left.

That still feels like a list, not cards.

---

# 2. Card styling details

Each speaking card should have:

- large rounded corners;
- soft but visible shadow;
- subtle layered effect;
- light background tint;
- small decorative accent such as a star, sparkle, microphone, speech bubble, or abstract classroom icon;
- number styling that feels integrated, not like a default square badge.

Example structure of one card:

- top-left or top area: number
- center: student name
- optional small label: “Speaking order”
- optional tiny decorative icon

The student name must remain very readable.

---

# 3. Animation for Set the Order

Before showing the final order, add a short **shuffle / dealing animation**.

Desired sequence:

1. User clicks `CREATE ORDER`
2. A small card deck animation appears
3. Cards quickly shuffle
4. Cards are placed onto the board one by one
5. Final speaking order remains visible

Animation should be short, about **1–1.5 seconds**.

---

# 4. Pick a Student — exact visual direction

For **Pick a Student**, the result should appear as a **single large reveal card**.

Do not just show text in the middle of the page.

Use:

- one central large card;
- subtle glow or spotlight;
- quick name shuffle;
- final card reveal.

The chosen student should appear on a real card, not just as plain large text.

---

# 5. Pick & Speak — exact visual direction

This mode should use **two real cards**:

1. a **student card**
2. a **question card**

Desired sequence:

1. names shuffle;
2. one student card is revealed;
3. then a second question card appears below or behind it;
4. the final result looks like a small game setup.

The question should appear inside a proper card, not just inside a text panel.

---

# 6. Make Pairs — correction

The puzzle approach is not working well visually.

Do **not** force awkward puzzle-piece shapes if they look clumsy.

Instead, use a cleaner visual metaphor:

## Better direction for pairs

Each pair should be shown as:

- two separate small cards connected together;
- or two overlapping flashcards;
- or two cards clipped/linked as one pair unit.

For example:

- Card 1: Anna
- Card 2: Leo
- both presented as a matched pair set

This should look neat and intentional.

Do not use ugly or overly literal jigsaw outlines if they reduce visual quality.

---

# 7. Make Teams — better direction

Teams should also use card logic.

Each team can be shown as:

- a coloured team panel containing multiple student cards;
- or a team board with cards placed inside it.

Students inside teams should still visually feel like cards or mini-cards.

---

# 8. What NOT to do

Do not interpret “cards” as:

- small decorative background cards;
- icon-only decorations;
- plain rows inside a big container;
- standard dashboard cards with list content.

Do not keep the result area looking like a normal productivity app.

Do not use boring row-based layouts if the goal is to make the tool visually engaging.

---

# 9. What TO do

Use actual **large game-like cards as the core result components**.

The visual result should feel closer to:

- a classroom card game;
- a deck of speaking cards;
- interactive flashcards;
- playful educational game UI.

---

# 10. Priority

Priority order:

1. make the result items visually become real cards;
2. improve Set the Order first;
3. improve Pick & Speak second;
4. simplify Make Pairs if needed, but make it cleaner and prettier.

It is better to have **beautiful cards** than a weak puzzle metaphor.

---

# 11. Final expectation

I want the result area to feel like a **card-based classroom game**, not a list-based app with decorations.

If necessary, redesign the result components again from scratch, but preserve the current functionality.
